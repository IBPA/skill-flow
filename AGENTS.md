# Project instructions

- Keep code files under 300 lines.
- Use Pydantic `BaseModel` for models, not dataclasses.
- In tests, build configs with required fields through fixtures or helpers such as `make_config()`.
- Commit or push only right after the user invokes `/commit-push`, `/lazy-commit-push`, or `/create-pr`; otherwise change only the working tree.
- Paper tables and figures are generated by `analysis/results/` into the sibling repo `../skill-flow-manuscript` (override with `SKILLFLOW_MANUSCRIPT_DIR`). Paper sources, LaTeX builds, and Overleaf sync live there.
- The `skill_flow.cli` subcommands are only `build-index`, `search`, and `pipeline`. Retriever and reranker experiments run through `scripts/run-*.py`.
- `integration/skillsbench` is a vendored checkout with its own `pyproject.toml` and environment; run its tooling from inside it.
- Gemini benchmark runs are bound by AI Studio quotas: keep `environment.n_concurrent` conservative and resume with `retry.resume` after daily-quota exhaustion.
